# DB Optimizer — веб-интерфейс

Ветка `extras/indexes` использует живой NestJS API: карточки и количество результатов берутся из PostgreSQL, порядком ленты управляет сервер через Redis. Здесь нет mock-данных, 3D-просмотра или фонового опроса. [Демо GitHub Pages](https://sachaxodev.github.io/database-query-optimizer-frontend/) по-прежнему относится к ветке `main`.

## Запуск

1. В локальном [репозитории бэкенда](https://github.com/SachaXoDev/Khodina_IU5-51B_Web_Labs_2026_Database_query_optimizer) используйте ветку `extras/indexes`. Поднимите NestJS на `127.0.0.1:3108` и настройте отдельные PostgreSQL, Redis и MinIO по разделу «Дополнительное задание: индексы, пагинация и Redis» в `database_query_optimizer/README.md`. Для проверки пагинации загрузите демонстрационные данные скриптом `scripts/demo_optimizer_seed.sql` этой ветки после инициализации схемы.
2. В корне этого репозитория с Node.js 22.12+:

   ```sh
   npm ci
   npm run lint
   npm run build
   npm run dev
   ```

   Откройте <http://127.0.0.1:5175>. Vite проксирует `/api`, `/media` и `/assets/default_index.svg` на NestJS как в `dev`, так и в `preview`. Если NestJS слушает другой адрес, задайте `API_PROXY_TARGET`, например `API_PROXY_TARGET=http://127.0.0.1:3000 npm run dev`.

## Проверка в браузере

1. Откройте `/?cardinality=420042`. После загрузки демонстрационных данных ожидается 750 совпадений и 32 страницы. В Network должен быть `GET /api/indexes?limit=24&offset=0&minCardinality=420042`. Нажмите «Далее» внизу списка и проверьте `offset=24`, затем последнюю страницу (`offset=744`, 6 карточек). При сбросе фильтра каталог возвращается на первую страницу без `minCardinality`. Несмотря на имя параметра, сервер фильтрует по точному равенству.
2. Откройте карточку и убедитесь, что `/detail/:id` читает `GET /api/indexes/:id`. В ленте `/feed` проверьте `GET /api/indexes/feed`. Нажмите «Далее»: запрос `GET /api/indexes/feed?next=true&id=…` продвигает курсор (ID — защита от повторного перехода); `position` меняется, а обычный `/feed` читает текущее положение без перехода. Для прямой сверки HTTP с Redis запустите из корня бэкенда `python3 scripts/verify-feed.py --redis-port <порт Redis>` на отдельном демостенде. После загрузки карточки этот фронтенд не опрашивает сервер по таймеру.
3. Дополнительно: зарегистрируйтесь, войдите, создайте черновик на `/create` и опубликуйте его. Изображение необязательно (до 50 МиБ); без него используется локальная обложка. Отметки «Нравится» и удаление своего индекса обращаются к API.

## Раздача сборки

При раздаче `dist/` настройте SPA fallback на `index.html` для `/feed`, `/detail/:id`, `/create`, `/login`, `/register` и прокси для API и серверных медиа. Отдавайте сборочные файлы `/assets/*` с фронтенда, за исключением указанного выше серверного ресурса. Вместо прокси можно задать `VITE_API_ORIGIN` при сборке; API должен разрешать credentialed CORS, а origin API и фронтенда должны оставаться same-site для cookie `SameSite=Lax`. Подписанные ссылки MinIO загружаются напрямую, поэтому хранилище должно быть доступно браузеру.
