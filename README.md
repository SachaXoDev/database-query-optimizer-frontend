# Database Query Optimizer — Frontend (React SPA)

Клиентская часть веб-приложения **«Оптимизатор запросов баз данных (Indexes Catalog)»** в рамках курса «Проектирование систем и продуктовая веб-разработка / РИП» (МГТУ им. Н.Э. Баумана, кафедра ИУ5).

Проект представляет собой мобильно-ориентированное одностраничное приложение (Single Page Application, SPA) для каталогизации, подбора и тестирования конфигураций индексов в реляционной СУБД PostgreSQL (B-Tree, BRIN, Hash, GIN).

---

## 1. Стек технологий

* **Фреймворк:** [React 19](https://react.dev/) (чистые функциональные компоненты и React Hooks)
* **Язык программирования:** [TypeScript 5](https://www.typescriptlang.org/)
* **Сборщик и Dev-сервер:** [Vite 6](https://vite.dev/)
* **Маршрутизация:** [React Router DOM v7](https://reactrouter.com/) (вложенные маршруты, `Outlet`, `useOutletContext`)
* **Компоненты интерфейса:** [React-Bootstrap 2](https://react-bootstrap.netlify.app/) & [Bootstrap 5](https://getbootstrap.com/)
* **Стилизация:** Кастомная темная тема (`#0d0e10`, акцентный неоновый зеленый `#1fdc6f`, адаптивный мобильный фрейм 390×844 px)

## 2. Архитектура и требования ЛР-5

1. **Автономная работа на Mock-данных:**
   * В соответствии с заданием ЛР-5 приложение полностью функционирует на стороне клиента без обязательного подключения к бэкенду, PostgreSQL и MinIO/S3.
   * Данные хранятся в модуле `src/modules/mock.ts`, а функции в `src/modules/indexesApi.ts` имитируют асинхронные HTTP-запросы с помощью задержек `setTimeout`.
2. **Отказоустойчивый медиа-слой (Fallback Media):**
   * При отсутствии ссылки на обложку/видео или при ошибках загрузки сети автоматически подставляются локальные статические ресурсы: `/DefaultImage.jpg` и `/DefaultVideo.mp4`.
   * На карточках с дефолтным изображением выводится зеленый бейдж `default image` (`src/components/IndexCard.tsx`).
3. **Управление состоянием без Redux и Context API:**
   * Вся коллекция карточек хранится в корневом состоянии `useState<IndexItem[]>(MOCK_INDEXES)` внутри макета `src/AppLayout.tsx`.
   * Доступ страниц к списку и функции обновления осуществляется через стандартный механизм React Router: `<Outlet context={{ cards, setCards }} />` и хук `useOutletContext<AppOutletContext>()`.
4. **Фильтрация по Cardinality (мощности столбца):**
   * Реализована через контролируемые компоненты `FilterBar`: поле ввода `Form.Control`, ползунок `Form.Range` и кнопку `Button`.
   * Фильтрация mock-данных выполняется по строгому равенству (`===`) в соответствии с бизнес-логикой ЛР-2.

## 3. Страницы приложения, элементы управления и поля

В приложении реализован адаптивный мобильный интерфейс (390×844 px). Для режима гостя в ЛР-5 активны две основные страницы (**«Плитка»** и **«Лента»**), а также доступна вспомогательная страница детального просмотра (**«Подробнее»**).

### 3.1. Страница каталога «Плитка» (`ListPage.tsx`, маршрут `/`)
Основная страница каталога услуг для поиска, фильтрации и выбора конфигураций индексов в виде сетки из 2 колонок.

* **Поля ввода и фильтрации (компонент `FilterBar`):**
  * **Поле ввода мощности `Form.Control` (числовое/текстовое):** плейсхолдер *«Мощность Cardinality (напр. 10000)»*. Предназначено для ручного ввода точного значения мощности.
  * **Интерактивный ползунок `Form.Range` (слайдер):** непрерывная шкала от `0` до `5 000 000+` для удобного визуального выбора мощности пальцем или курсором.
  * **Числовые маркеры диапазона:** текстовые метки границ `0` (слева) и `5M+` (справа).
* **Кнопки управления:**
  * **Кнопка «Найти» (`Button`, класс `.btn-search-action`):** отправляет форму фильтрации и инициирует асинхронный поиск по заданному значению Cardinality.
  * **Кнопка удаления карточки «✕» (класс `.tile-delete-btn`):** расположена в правом верхнем углу каждой карточки. Вызывает модальное окно подтверждения (`confirm(...)`) и выполняет локальное логическое удаление карточки из каталога без перезагрузки страницы.
  * **Кнопка-бейдж лайка (класс `.tile-likes-badge`):** интерактивная кнопка в левом нижнем углу превью с иконкой сердца и счетчиком лайков. Клик по бейджу ставит/снимает лайк и инкрементирует счетчик без перехода со страницы (с обработчиком `e.stopPropagation()`).
  * **Кнопка «Сбросить фильтр»:** появляется по центру экрана при отсутствии совпадений по фильтру для мгновенного сброса поискового запроса.
* **Отображаемые поля данных карточки (`IndexCard`):**
  * Превью изображения услуги (с автоматической подстановкой `DefaultImage.jpg` при отсутствии URL);
  * Зеленый бейдж-индикатор **`default image`** (сигнализирует о срабатывании fallback-медиа);
  * Название конфигурации индекса (`indexName`, например `idx_orders_customer_id`);
  * Связка таблицы и столбца (`tableName.columnName`);
  * Тип индекса (`indexType`: B-Tree, BRIN, Hash, GIN);
  * Краткое описание оптимизации (`shortDescription`);
  * Метрики: мощность столбца (`CARDINALITY`) и оценочное время построения (`~Xs`).
* **Действие по клику на карточку:**
  * Клик по телу карточки осуществляет бесшовный переход в полноэкранную ленту к выбранной услуге: `navigate('/feed?id=' + item.id)`.

---

### 3.2. Страница «Лента» (`FeedPage.tsx`, маршрут `/feed`)
Полноэкранный вертикальный медиа-слой в стиле TikTok / Reels для динамичного просмотра видеодемонстраций и метрик индексов.

* **Поля отображения данных:**
  * **Фоновый медиа-слой:** циклический видеопоток `<video autoPlay loop muted>` (или фоновое изображение `<img>` при отсутствии видео, с автоматическим fallback на `DefaultVideo.mp4`);
  * **Верхний статус-бар бренда:** пульсирующая зеленая точка `.live-dot` (индикатор активности) и логотип `DB OPTIMIZER`;
  * **Теги типа и расположения:** бейджи-плашки `[Тип] Index` и `[Таблица].[Столбец]`;
  * **Заголовок услуги:** крупное наименование индекса (`indexName`);
  * **Поле текстового описания:** блок `fullDescription` / `shortDescription` со стилями ограничения высоты текста.
* **Кнопки управления и интерактивные элементы:**
  * **Кнопка «Лайк» (`.vibes-action-btn`, боковая панель справа):** круглая кнопка с иконкой сердца и счетчиком лайков. При нажатии инвертирует статус `isLiked` (0 $\leftrightarrow$ 1), обновляет счетчик в едином стейте и подсвечивается неоновым зеленым цветом `#1fdc6f`.
  * **Кнопка «Далее» (`.vibes-action-btn`, боковая панель справа):** круглая кнопка со стрелкой вниз и подписью «Далее». Осуществляет циклический переход к следующей услуге в коллекции (`(currentIndex + 1) % cards.length`).
  * **Информационные плашки метрик (боковая панель справа):**
    * Плашка `CARDINALITY` — текстовое поле с числовым значением мощности индекса;
    * Плашка `ВРЕМЯ` — текстовое поле с расчетным временем создания (`~Xs`).
  * **Кнопка раскрытия описания «больше / меньше» (`.desc-toggle-btn`):** переключает режим отображения текста между свернутым (3 строки) и развернутым полным описанием плана EXPLAIN.

---

### 3.3. Вспомогательная страница «Подробнее» (`DetailPage.tsx`, маршрут `/detail/:id`)
Страница детального просмотра параметров конкретной услуги по прямому URL-маршруту.

* **Поля отображения данных:**
  * Полноэкранный медиа-слой выбранного индекса (видео/обложка);
  * Название индекса, связка таблицы и столбца, плашки мощности и времени создания;
  * Полное описание оптимизации запроса.
* **Кнопки управления:**
  * **Кнопка «✕ Закрыть» (в левом верхнем углу):** закрывает экран детального просмотра и возвращает пользователя в каталог-плитку (`navigate(ROUTES.LIST)`).
  * **Кнопка «Далее»:** переход к детальному просмотру следующего индекса (`/detail/:nextId`).
  * **Кнопка «больше / меньше»:** сворачивание/разворачивание описания.

---

### 3.4. Фирменная нижняя панель навигации (`TabBar.tsx`, 4 пункта меню)
Закреплена в нижней части мобильного фрейма (`position: absolute; bottom: 0; height: 64px; z-index: 20`) и присутствует на всех экранах приложения:

| № | Пункт меню | Иконка | Статус в ЛР-5 | Действие / Поведение |
|---|---|---|---|---|
| 1 | **Лента** | Play (треугольник) |  **Активен** | Переход на страницу ленты `navigate(ROUTES.FEED)`. |
| 2 | **Добавление** | Плюс в окружности | 🔒 **Заблокирован** | Атрибут `disabled`, класс `.tab-item.disabled` (недоступно гостю). |
| 3 | **Плитка** | Сетка 2×2 квадрата |  **Активен** | Переход в каталог-плитку `navigate(ROUTES.LIST)`. |
| 4 | **Вход** *(справа)* | Профиль пользователя | 🔒 **Заблокирован** | Атрибут `disabled`, класс `.tab-item.disabled` (будет реализован в ЛР-6). |

## 5. Задействованные хуки React

* **`useState`**:
  * Управление локальным состоянием фильтра `cardinality` и флага загрузки `loading` (`ListPage.tsx`);
  * Управление текущим индексом видео в ленте `currentIndex` и флагом раскрытия текста `isExpanded` (`FeedPage.tsx`);
  * Хранение единого списка карточек `cards` в `AppLayout.tsx`.
* **`useEffect`**:
  * Синхронизация выбранной услуги по query-параметру `?id=` при переходе из каталога в ленту;
  * Первичная инициализация каталога mock-данными.
* **`useOutletContext`**:
  * Проброс и мутация состояния `cards` между несвязанными маршрутами без сторонних библиотек.
* **`useNavigate`, `useSearchParams`, `useParams`**:
  * Программная навигация между страницами и чтение параметров адресной строки.

## 6. Установка и запуск

### Предварительные требования
* [Node.js](https://nodejs.org/) версии $\ge 18.0$
* Пакетный менеджер `npm`

### Запуск в режиме разработки
```bash
# 1. Перейти в каталог фронтенда
cd frontend

# 2. Установить зависимости
npm install

# 3. Запустить dev-сервер Vite
npm run dev
```
После запуска откройте в браузере: **`http://localhost:5173`** (или порт, указанный в терминале).

### Сборка для продакшена
```bash
npm run build
```
Готовая статическая сборка будет сгенерирована в папку `dist/`.

### Предпросмотр продакшен-сборки
```bash
npm run preview
```
